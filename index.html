Sharding en PostgreSQL

Guía y casos de uso

Dividir una base grande para escalar sin perder coherencia.

El sharding divide los datos de una tabla grande entre varios servidores para escalar horizontalmente cuando un único nodo ya no alcanza en almacenamiento, escrituras o CPU.

Sharding Reparte filas entre varios servidores
Particionamiento Divide una tabla dentro de un mismo servidor
Replicación Copia todo el dataset a otros nodos

La clave principal es elegir una shard key coherente, porque todas las consultas de un usuario, cliente o tenant deben poder dirigirse a un solo shard. Cuando eso se hace bien, el sistema escala sin perder un modelo simple de lectura y escritura.
